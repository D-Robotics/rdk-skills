# X5 工作区

## 1. 工作区概览

本 Pack 是 D-Robotics X5 OpenExplorer 的 Agent Skill Pack V2，仅覆盖 X5 芯片。

- 工作区根目录：`.drobotics-x5/`
- 版本文件：`.drobotics-x5/VERSION`
- Skill 索引：`.drobotics-x5/skill-index.json`
- 随包离线资料目录（可选）：`.drobotics-x5/docs/`
- Skill 目录：`.drobotics-x5/skills/`
- 平台资产：`.drobotics-x5/platforms/x5/`
- 源码与 Skill 发布版本：`1.1.1`（见 `VERSION` 和各 `SKILL.md` frontmatter）。
- 平台运行合同版本：`2.0.0`（见 `platforms/x5/skill-index.json`；与源码发布版本分开管理）。

## 2. 使用规则

- 遇到 X5 OpenExplorer 请求时，先使用 `.drobotics-x5/skills/x5-router/SKILL.md` 作为顶层路由 Skill。
- x5-router 先读平台索引中的 `routing_policy`、`intents`、`accepts` 和 `handoffs`，再按输入、产物、环境和风险选择一个主 Skill，并生成 `route.json`。
- 用户未指定量化方法且提供 ONNX/Caffe 模型时默认优先 PTQ；明确要求 QAT 或 PTQ 评测证明目标无法达到时再进入 QAT。仅有 `.pt/.pth` 或 PyTorch 源码不能自动推断 QAT。
- OE 官方强烈建议使用 Docker。PTQ/QAT 工作流默认检查匹配版本的 X5 OE Docker；宿主机 CLI 只有在用户明确设置 `--execution-mode host`（或 `OE_DROBOTICS_EXECUTION_MODE=host`）后才可使用，不因 Docker image 缺失自动回退。
- 工具链命令、参数、API、版本门槛和流程细节必须依据 D-Robotics 官方文档核对；路由用 Skill/index，事实用文档证据。
- 不要求机器安装 OE 离线文档包。`search_local_docs.py` 和包内 Markdown 仅是可选的离线辅助材料，不能作为官方依据或替代 MCP 检索。

## 3. 执行前检查

- 开始 X5 工具链任务前，先检查用户是否提供了可用板卡信息。
- X5 板卡按 X5 处理，使用 `bayes-e` march、`.bin` 产物格式。
- 优先从环境变量中查找板卡信息，例如 `X5_BOARD_IP`、`BOARD_TYPE`、`BOARD`。
- 如果环境变量没有提供，再检查项目内相关配置文件。
- 如果任务涉及板端运行但没有找到板卡信息，必须先向用户确认。
- 板端 Python API 的版本支持必须按官方 MCP 页面原文确认；版本边界不明确时，还需在目标板验证包来源并实际导入 API。

## 4. 强制边界

- **PTQ**：`hb_mapper`、`bayes-e`、`.bin`。
- **Plugin QAT**：`March.BAYES_E`、`check_model`、`compile_model`/`export_hbir`、`.hbm/.hbir`。
- **排除**：HAT、HAT config、Trainer、Model Zoo、`tools/compile_perf.py`。
- **隔离**：X3、S 系列模型、Runtime、wheel/DEB 和命令不得复用。
- `March.BAYES` 属于 J5，不得复制到 X5。

## 5. 官方文档 MCP 检索规则

凡是要给出或执行 X5 OE 的命令、参数、API、版本门槛、配置项、流程顺序、默认行为或错误码，必须先从官方文档 MCP 检索并读取原文：

1. 调用 `mcp__rdk_docs__search_docs`，设置 `manual="oe-x5"`、`source="docs"`，用当前问题中的工具/API/版本与目标阶段构造查询。
2. 只选择返回的 `developer.d-robotics.cc` 官方文档 URL；社区论坛结果不能支撑官方命令或 API。
3. 对选中的 URL 调用 `mcp__rdk_docs__get_page`，从页面正文确认适用芯片、手册版本和具体细节。搜索摘要不能单独作为依据。
4. 将查询、手册、页面标题与 URL 记录到执行计划或结果中。

- 若 MCP 不可用、没有匹配的 X5 官方页面、页面读取失败，或页面没有回答精确版本/兼容性边界，停止依赖该细节的操作并报告阻塞原因；不得从本地资产、旧输出或其他芯片手册补猜。
- X5 OE 事实优先查 `oe-x5`；板端 RDK X5 Python API 可查 `rdk-x`，并须再次核对页面中的芯片型号与适用版本。`rdk-x` 页面写明 “3.5.0 版本之后”，故不能改写成 `>= 3.5.0`。版本正好为 3.5.0 时，要求 MCP 页面复核及目标板包来源/实际导入证据；证据不足再保持阻塞。
- `.drobotics-x5/docs/`、`_sources/` 路径和本地 `hbm_runtime` Markdown 均不是 MCP 官方证据。缺少离线手册不影响环境探测的 `ready` 状态；具体工具链操作仍须完成本节的 MCP 核验。
- 获取固定版本 SDK、文档或 Docker 离线制品时，按 `.drobotics-x5/docs/offline-artifact-delivery.md` 处理制品来源；该指南不替代官方 API/命令核验。

# 嵌入式通用规则

## Reset 引脚翻转次数下限
添加或修复 reset 操作代码时,reset 引脚**至少要翻转两次**(即对 reset 引脚相关寄存器至少写入 2 次,典型为"先复位配置再拉有效电平"两步,中间含必要延时)。
若手册或参考代码看起来只翻转了一次:
1. 不得直接照搬"一次"的结论,必须再次详细确认手册/参考代码是否真的只翻转一次(完整读全 reset 写入序列,含封装函数内部对 reset 引脚寄存器的每一次实际写入,不止看函数调用次数)。
2. 确认后确实只翻转一次 → **停下通知用户**,询问是否继续按一次执行,不得擅自按一次写代码。翻转至少两次时,**按手册/参考代码给出的具体翻转次数修改代码**(实际是几次就写几次,不擅自增减)。

## 未用代码检查(强制)

给用户 review 的代码修改和直接进行的代码修改,都必须检查并将未用到的代码去掉——即使该代码在参考修改(参照的现有驱动/历史 diff)中存在,只要在本次新增/修改的文件中无实际使用点,就去掉,不盲目照搬。

检查方法:对本次生成或修改的每一个符号(宏、变量、函数、结构体字段等),回查其在所属文件及调用方是否存在实际引用;无引用即视为未用到,去掉。

目的:防止"参照代码里有所以照搬"导致引入死代码(如定义了但未使用的寄存器宏)。参考代码仅作风格/结构参照,不代表其每一项都适用于本 sensor,是否保留以"有无使用点"为准。

## 驱动能力与上下拉电阻强度

排查"驱动能力"时，GPIO/I2C 寄存器常无独立 drive strength 字段，由上下拉电阻强度位体现：电阻值越小驱动越强，电阻值越大驱动越弱。设备树 `drive-strength` 是电流值（mA），方向相反：电流值越高驱动越强，电流值越小驱动越弱。

## I2C 命令规范（i2cdetect / i2ctransfer）

板端用 i2c-tools 访问 SER/DES/Sensor，统一用以下命令形式，不得改用其它写法。

**i2cdetect** — 扫描总线上存在的设备地址，用于定位 I2C 是否通：

```bash
i2cdetect -y -r <bus>
```

**i2ctransfer** — 访问 16bit 寄存器地址的设备（SER/DES/大多数 sensor）：

| 操作 | 命令 |
|------|------|
| 读 1 字节 | `i2ctransfer -y -f <bus> w2@<dev> <addr_hi> <addr_lo> r1` |
| 读 2 字节 | `i2ctransfer -y -f <bus> w2@<dev> <addr_hi> <addr_lo> r2` |
| 写 1 字节 | `i2ctransfer -y -f <bus> w3@<dev> <addr_hi> <addr_lo> <data>` |
| 写 2 字节 | `i2ctransfer -y -f <bus> w4@<dev> <addr_hi> <addr_lo> <data_hi> <data_lo>` |
| 定时读（1 秒间隔） | `watch -n 1 i2ctransfer -y -f <bus> w2@<dev> <addr_hi> <addr_lo> r<length>` |
